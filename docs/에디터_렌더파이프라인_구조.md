# PixiJS 기반 영상 편집기 렌더링 아키텍처 정리

## 1. 전체 결론 요약

- 트랙은 Container로 표현한다
- 클립은 트랙 아래에 고정된 논리 객체다
- Adjustment Layer는 실제 레이어가 아니라 시간 조건이 있는 렌더 패스 규칙이다
- Adjustment Layer는 RenderTexture + Sprite + Filter로 구현한다
- RenderLayer는 UI / Overlay용 렌더 경계로만 사용한다
- visible은 “존재 여부”만 담당한다
- 렌더 파이프라인 분기는 별도로 계산한다
- addChild / removeChild는 빈번해도 성능 문제 거의 없다
- 진짜 성능 비용은 RenderTexture 렌더 + 필터다

---

## 2. 핵심 개념 구분

[Container]
- 논리적 그룹
- 트랙, 클립 구조 표현
- 렌더 경계 아님

[RenderLayer]
- GPU 렌더 경계
- 상태(state) 분리용
- offscreen 렌더 아님
- UI / Overlay / Gizmo 용도

[RenderTexture]
- offscreen 렌더 대상
- Adjustment Layer 구현의 핵심
- GPU 비용 큼

---

## 3. Adjustment Layer의 실제 정체

Adjustment Layer는 Display Tree에 존재하는 노드가 아니다.

“이 시간 구간에 존재하는 특정 트랙/클립의 결과를  
한 번 캡처해서 필터를 적용하라”는 렌더 규칙이다.

Premiere / After Effects도 동일한 개념을 사용한다.

---

## 4. 프레임 단위 렌더링 흐름 (정석)

time →
1. 현재 시간에 활성화된 클립 계산
2. Adjustment Layer 영향 여부 계산
3. 영향을 받는 클립 → RenderTexture로 렌더
4. 영향을 받지 않는 클립 → world(Container)로 렌더
5. RT → Sprite → Filter → stage 합성

---

## 5. 렌더 분기 핵심 규칙

한 클립은 한 프레임에 하나의 렌더 경로만 탄다.

[잘못된 방식]
- world에 그리고
- 조건 만족 시 RT에도 한 번 더 그림 (중복 렌더)

[올바른 방식]
- 조건에 따라 렌더 경로 자체를 분기

예시:

if (isAffectedByAdjustment(clip, time)) {
adjustmentQueue.push(clip)
} else {
normalQueue.push(clip)
}

---

## 6. visible 사용 원칙

[visible이 담당하는 역할]
- 이 클립이 현재 시간에 존재하는가
- 컷 인 / 컷 아웃 표현

[visible이 하면 안 되는 역할]
- 렌더 파이프라인 선택
- Adjustment Layer 분기

정리:
visible은 “살아있나”만 판단한다  
“어디로 그릴지”는 렌더 큐가 판단한다

---

## 7. addChild / removeChild 성능 정리

결론:
- 프레임 단위 add/remove → 안전
- CPU 작업이며 GPU 비용 거의 없음

실제로 무거운 작업:
- RenderTexture 렌더
- Blur / Shader 필터
- FBO 전환

정리:
성능 병목은 구조 변경이 아니라 픽셀을 다시 그리는 것이다

---

## 8. 권장 기본 구조

Stage
├─ world (Container)
│   ├─ backgroundTrack (Container)
│   ├─ videoTrack1 (Container)
│   ├─ videoTrack2 (Container)
│   └─ textTrack (Container)
└─ uiLayer (RenderLayer)

Adjustment Layer는 별도의 Display Tree 노드가 아니라  
렌더 단계에서만 존재한다.

---

## 9. 구현 권장 순서

1. 구조를 단순하게 시작한다
2. 프레임 단위로 렌더 큐를 재구성한다
3. add/remove 최적화는 나중에 한다
4. RenderTexture / Filter 개수를 최소화한다
5. 실제 성능 이슈가 생기면 diff / 캐싱을 도입한다

---

## 10. 한 문장 핵심 정리

영상 편집기는 Scene Graph 기반 앱이 아니라  
프레임 단위 Render Queue 엔진이다
