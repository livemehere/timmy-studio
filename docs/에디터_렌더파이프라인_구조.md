# PixiJS 기반 영상 편집기 렌더링 아키텍처 정리

## 1. 전체 결론 요약

- 트랙은 `Container`로 표현한다
- 클립은 트랙 아래에 고정된 논리 객체다
- Adjustment Layer는 실제 레이어가 아니라 **시간 조건이 있는 렌더 패스 규칙**이다
- Adjustment Layer는 `RenderTexture + Sprite + Filter`로 구현한다
- `RenderLayer`는 UI / Overlay용 **렌더 경계**로만 사용한다
- `visible`은 “존재 여부”만 담당한다
- 렌더 파이프라인 분기는 별도로 계산한다
- `addChild / removeChild`는 빈번해도 성능 문제 거의 없다
- 진짜 성능 비용은 `RenderTexture 렌더 + 필터`다

---

## 2. 핵심 개념 구분

### Container
- 논리적 그룹
- 트랙, 클립 구조 표현
- 렌더 경계 아님

### RenderLayer
- GPU 렌더 경계
- 상태(state) 분리용
- offscreen 렌더 아님
- UI / Overlay / Gizmo 용도

### RenderTexture
- offscreen 렌더 대상
- Adjustment Layer 구현의 핵심
- GPU 비용 큼

---

## 3. Adjustment Layer의 실제 정체

Adjustment Layer는 Display Tree에 존재하는 노드가 아니다.

> “이 시간 구간에 존재하는 특정 트랙/클립의 결과를  
> 한 번 캡처해서 필터를 적용하라”는 **렌더 규칙**

Premiere / After Effects도 동일한 개념을 사용한다.

---

## 4. 프레임 단위 렌더링 흐름 (정석)

```text
time →
1. 현재 시간에 활성화된 클립 계산
2. Adjustment Layer 영향 여부 계산
3. 영향을 받는 클립 → RenderTexture로 렌더
4. 영향을 받지 않는 클립 → world(Container)로 렌더
5. RT → Sprite → Filter → stage 합성
